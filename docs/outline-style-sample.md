# Outline, Style, and Sample

## Outline

Transform source material into a presentation narrative rather than copying the document structure.

For each slide define:

- slide number;
- role;
- proposed title;
- 2–4 core messages;
- intended visual structure;
- required source assets.

Prefer one main visual story per slide.

## Visual direction

When the user has not supplied a reference, propose only 2–3 suitable directions from `references/style-catalog.md`.

The approved `visual_spec.md` should explicitly capture:

- palette;
- typography character;
- hierarchy;
- spacing/density;
- diagram/illustration language;
- chart/figure treatment;
- recurring motifs;
- asset treatment;
- text repairability;
- hard constraints;
- negative constraints.

## Representative sample

Choose a content-rich middle slide that stress-tests the intended visual system.

Avoid using a title slide as the default sample because it does not sufficiently test:

- body text;
- diagrams;
- labels;
- text-repairability;
- density;
- source-asset integration.

Once approved, the sample becomes the single primary visual anchor for the deck.
